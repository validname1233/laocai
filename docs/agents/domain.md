# Domain Docs

本文档说明各工程 skill 在探索本代码库时应如何使用领域文档。

## 探索前需要读取的文档

1. 先读取根目录的 **`CONTEXT-MAP.md`**，确定当前任务涉及哪些上下文。
2. 读取与当前任务相关的各个 `CONTEXT.md`。
3. 读取根目录 **`docs/adr/`** 中与当前工作区域相关的系统级 ADR。
4. 如果当前上下文存在自己的 `docs/adr/`，也读取其中相关的上下文级 ADR。

如果这些文件不存在，静默继续即可。不要把它们的缺失当成问题，也不要提前建议创建。只有在术语或决策实际确定时，才通过 `/domain-modeling` 按需创建。

## 上下文布局

本仓库采用 multi-context 布局。上下文索引位于根目录 `CONTEXT-MAP.md`，其中列出每个上下文的领域文档、作用范围以及上下文之间的关系。

当前上下文包括：

- **Bot 框架上下文**：由根目录 `CONTEXT.md` 定义，主要覆盖 `laocai-bot-spring-boot-starter` 以及框架核心代码。
- **AI 主动对话上下文**：由 `laocai-app/CONTEXT.md` 定义，覆盖 `laocai-app` 中的主动对话领域。

`bin/CONTEXT.md` 与根目录框架上下文内容相同，不作为第三个独立领域上下文。处理 `bin/` 下的内容时，将其视为框架上下文的补充副本。

## 使用术语表中的词汇

当输出中需要命名领域概念（例如 issue 标题、spec、重构提案、假设或测试名称）时，使用相关上下文 `CONTEXT.md` 中定义的术语。不要改用术语表明确避免的同义词。

如果需要的概念不在相关术语表中，这说明可能存在以下情况：

- 当前使用了项目尚未采用的表达，应重新考虑命名；或者
- 项目确实缺少该领域概念，应记录下来并交由 `/domain-modeling` 处理。

如果一个概念跨越多个上下文，优先使用其定义所在上下文的术语，并在输出中明确上下文边界。

## 跨上下文依赖

`laocai-app` 可以使用 Bot 框架提供的 `Event`、`MessageEvent`、`Listener`、`Bot` 等概念和能力；Bot 框架不应反向依赖 AI 主动对话领域或具体业务逻辑。

## 标记 ADR 冲突

如果输出与现有 ADR 冲突，必须明确指出，不要静默覆盖：

> _与 ADR-0007 冲突，但值得重新讨论，因为……_
